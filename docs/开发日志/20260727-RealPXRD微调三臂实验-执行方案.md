## 0. 背景与必读结论

### 0.1 我们要解决的问题

当前 seeded-McMaille 融合流水线的瓶颈在**种子生成端**：
RealPXRD A2（xrd-only 消融，K=100）的候选池里，
「正确原胞」召回只有 **4%**（strict 口径，见 §5）。
本实验检验：**微调 RealPXRD 能否让它的 Top-100 种子更准。**

### 0.2 必须先知道的架构缺陷（决定实验设计）

**RealPXRD 的 XRD 编码器把 2θ 量化成整数度。**

`/nanolab/users/wyx/archive/RealPXRD-Solver/app/model/bert.py`：

```python
def batch_input(self, pxrd_x, pxrd_y, peak_num):
    ...
    return batch_peak_x.long(), batch_peak_y   # ← 2θ 被 .long() 截断

def forward(self, pxrd_x, pxrd_y, peak_num):
    src_pos, src_tokens = self.batch_input(pxrd_x, pxrd_y, peak_num)
    x = self.embed_tokens(src_tokens).squeeze(-2)         # 强度 → 32维（连续）
    pos_embed = self.embed_positions(src_pos).squeeze(-2) # int(2θ) → 32维（离散！）
    x = x + pos_embed
```

`embed_positions` 是 `nn.Embedding(180, 32)`，索引就是 `int(2θ)`。

**已实测验证**（用 `pretrained/weight/2501/pxrd-all` 权重）：

| 输入峰位 | 结果 |
|---|---|
| `20.10/28.70/35.40` vs `20.90/28.99/35.99`（差 0.8°） | **‖Δemb‖ = 0.0**，逐比特相同 |
| 整数部分 +1 | ‖Δemb‖ = 29.6 |

indexing 需要 ~0.01–0.05° 峰位精度。2θ≈30° 处 0.5° 误差 → \|Δd/d\| ≈ 3%，
已贴着 `ltol=0.05` 边界。**这是 A2 只有 4% strict 的根因。**

**推论**：任何「冻住该编码器」的方案都继承此量化误差，下游加层无法补回
（信息在输入端已销毁）。因此必须有一个解冻/替换位置编码的对照臂（臂 C）。

### 0.3 项目内先例

`docs/实验记录/20260715-A2-PeakTransformer-P0诊断与Fourier修复.md`：
自研 PeakTransformer 踩过同一个坑——Linear(g) 版 strict 5%，
换成 **16 个 log-spaced 频率的 Fourier features** 后 strict **97%**。
臂 C 的做法应参考此文件。

### 0.4 参考天花板

自研 6M peaks-only 模型（`scale_6m_a3_g1_gstar6_aug_bs512_seed42`）
MP100 Top-1 prim strict = **37%**。本实验不要求超过它，
目的是判断 RealPXRD 这条线是否值得继续投入。

## 3. 三个实验臂

### 臂 A —— 保持 A2 壳，继续 flow，只在 output 加层

**目的**：用户原始提案，作对照下界。

- 加载完整 `CSPFlow`（`xrd_encoder` + `decoder`）
- **A2 化**（与现有推理消融一致）：
  - `num_atoms = 1`，`atom_types = [DUMMY_ATOM_TYPE=1]`
  - `node_embedding` 查表结果 **置零**（`torch.zeros_like`）
  - `frac_coords` 固定 `0.5`，**不更新坐标**
- **加层**：在 `decoder.lattice_out` 前插入一个新的 MLP
  （`512 → 512 → 512`，SiLU + LayerNorm，残差连接），
  再接一个**新初始化**的 `Linear(512, 9)` 替换原 `lattice_out`
- **训练**：仍用 flow matching，但 `cost_coord = 0`，只留晶格项
  `loss = MSE(pred_l, rand_l)`
- **可训参数**：新加的 MLP + 新 `lattice_out`；
  `xrd_encoder` 冻结；`decoder` 主体（CSP 层）冻结
- **推理**：走 `CSPFlow.sample()` 的晶格 ODE（200 步），
  `num_evals=100` 得到 Top-100

### 臂 B —— 冻 Bert，砍掉 decoder/ODE，加 lattice head 监督回归

**目的**：检验预训练峰表征值不值钱。

```text
pxrd_x/pxrd_y/peak_num
  → BertModel (冻结, 加载 pxrd-all 权重)
  → F.normalize(out, dim=-1)          # 512-d
  → MLP: 512→512→256→6                # 只训这部分
     (每层 LayerNorm + SiLU + dropout 0.1)
  → 反归一化 → (a,b,c,α,β,γ)
```

- **不使用** decoder / CSPNet / flow / t / 坐标
- **损失**：`SmoothL1(pred_norm, target_norm)`；
  建议追加体积项 `|log(V_pred/V_true)|`，权重 0.1
- **Top-100 产生方式**：模型输出是**确定性单点**，
  用**确定性变体扩展**产生 K 个候选（Bravais 投影 + 轴置换 + 有限尺度因子），
  参考 `<本项目>/src/pxrd_cell_indexing/model/topk.py` 的 `build_top_k_candidates`。
  **不要**用随机采样凑 100 个。

### 臂 C —— 同 B，但把位置编码换成连续 Fourier(2θ)

**目的**：验证 §0.2 的量化是不是真瓶颈。**这是本实验最关键的一臂。**

在臂 B 基础上**只改一处**：替换 `BertModel` 的位置通路。

- 删除 `embed_positions = nn.Embedding(180, 32)` 的整数索引用法
- 改为对**连续** 2θ（或更好：`g = 1/d² ∝ sin²θ`）做 Fourier 编码：
  - 16 个 log-spaced 频率，输出 `[sin(2πf·g), cos(2πf·g)]`
  - 投影到 32 维后与 `embed_tokens(intensity)` 相加
  - 做法参考 `src/pxrd_cell_indexing/model/encoder/peak_transformer.py`
    （`peak_transformer_fourier_freqs=16`, `fourier_mode`）
- **可训参数**：新 Fourier 位置通路 + `sentence_encoder` 最后一层 + `out` + lattice head；
  其余 Bert 层保持加载的预训练权重并冻结
- 其余（数据、损失、Top-K 生成、评测）与臂 B 完全一致

> 臂 C 的位置编码换了，原 `embed_positions` 权重不再可用，属预期。
> 其余 Bert 权重仍从 `pxrd-all` 加载。

## 5. 评测口径（**不得修改**）

与项目既有分析完全一致：

- **loose** = `Lattice.find_mapping(ltol=0.05, atol=3.0)` 非空
- **strict** = loose 且 `|det(scale) − 1| < 0.25`
- **真值** = MP100 CIF → `SpacegroupAnalyzer.get_primitive_standard_structure()`
- 直接调用 `<本项目>/scripts/remeasure_l4_prim_vs_conv.py` 的 `l4()` 与 `truth_cells()`

### 必须报告的指标（对 MP100 全部 100 个样本）

| 指标 | 说明 |
|---|---|
| `library strict` | Top-100 池中**存在**正确原胞的样本比例 ← **主指标** |
| `library loose` | 同上，loose 口径 |
| `Top-1 / Top-5 / Top-20 strict` | 排序质量 |
| `best \|det\| 中位数` | 亚胞/倍胞倾向 |
| `中位 V_pool / V_truth` | 体积尺度偏移 |
| 近正交 / 近六方候选占比 | 对称性形态 |

### 基线对照表（已有数据，直接引用）

| 方案 | library strict | Top-1 strict | best \|det\| 中位 | 中位 V/V真 |
|---|---:|---:|---:|---:|
| RealPXRD A2 K=100（**待超越**） | **4%** | ~3% | 5.0 | 0.26 |
| 自研 6M peaks-only（参考天花板） | 39% | **37%** | 1.0 | ~1 |

## 6. 验收标准

**主判据：臂的 `library strict` 相对 A2 的 4%。**

| 结果 | 判定 |
|---|---|
| 某臂 ≥ **15%** | 该路线**成功**，值得继续投入 |
| 8% – 15% | 边际，需看 `best \|det\|` 与体积是否同步改善 |
| < 8% | 该臂**失败** |

**预期（供对照，不要据此改数据）**：
臂 A、B 因继承 2θ 量化，预计停在 4–8%；臂 C 若明显更高，
即坐实「瓶颈在输入表示，而非容量或微调方式」。

**结论要能回答的三个问题**：
1. 微调 RealPXRD 能否把种子 strict 召回抬到可用水平？
2. 预训练 Bert 表征相对随机初始化有没有增益？（需补一个随机初始化的臂 B 对照）
3. 2θ 整数量化是不是主瓶颈？（A/B vs C）

## 8. 执行注意事项

1. **不要修改评测口径**（§5）。历史数字全部按此口径产出，改了就无法比较。
2. **不要修掉 `augment_spectrum` 的 ±0.1° 被量化抹平**这一现象（§2.3），
   它是臂 A/B 的待观测行为。
3. 臂 A 的 A2 化必须与现有推理消融一致
   （`num_atoms=1` / 零 embedding / 坐标冻结 0.5 / 不更新坐标），
   否则与历史 A2 数字不可比。
4. 三臂必须用**同一份 10k 子集**。
5. 环境：`gfortran` 无关；Python 侧需 `torch`、`torch_geometric`、`torch_scatter`、
   `lmdb`、`pymatgen`、`hydra-core`、`lightning`。
   RealPXRD 仓库导入需 `sys.path.insert(0, '/nanolab/users/wyx/archive/RealPXRD-Solver')`。
6. `torch.load` 需 `weights_only=False`（Lightning ckpt）。
7. 单卡 24GB；臂 A 的 CSPNet(6层×512) 前向较重，注意 batch size。
8. 若某臂中途明显不收敛，**先记录现象再调**，不要静默改超参。
