# Reranker 设计与后续实验方案

> 2026-07-31 ｜ 目标：在**不改动 seed 生成、不改动 McMaille**的前提下，对 seeded-Mc 输出的 `.allcells`
> 候选做重排，把「已经在库里但没排到第一」的样本捞回 Top-1。

---

## 1. 为什么现在做重排：可捞空间的量化

重排是**纯重新排序**，库召回 `lib_strict` 由构造保证不变，能动的只有 Top-1 / Top-20。
所以 Reranker 的理论上限 = `lib_strict`，可捞空间 = `lib_strict − top1_strict`。

在冻结的 v4 池上实测（primitive L4-strict：`find_mapping(ltol=0.05, atol=3°) ∧ |det−1|<0.25`，
当前排序为 McM20 降序）：

| 集合 | K | 池中位/均值 | lib | Top-1 | 可捞空间 | 命中落在 rank 2–20 |
|---|---:|---:|---:|---:|---:|---:|
| MP100 | 100 | 10 / 12 | 59% | 49% | 10 pp | 10 / 10 |
| MP100 | 1000 | 33 / 45 | 69% | 50% | 19 pp | 19 / 19 |
| CNRS | 100 | 47 / 46 | 64.2% | 39.0% | **25.2 pp** | 27 / 31 |
| CNRS | 1000 | 188 / 183 | 68.3% | 31.7% | **36.6 pp** | 34 / 45 |

三个直接结论：

1. **主战场是 CNRS，不是 MP100。** MP100 K=100 只剩 10 pp，做到完美也就 59%；
   CNRS K=1000 有 36.6 pp，是全项目单点收益最大的位置。
2. **绝大多数可捞样本就在 Top-20 以内**（CNRS K=1000 是 34/45）。
   因此重排只需要在**短名单**上做，不必对 188 个候选全部精算重特征。
3. **K=1000 + Reranker 才是完整故事。** K=1000 把 CNRS 的 lib 从 64.2% 抬到 68.3%，
   但 McM20 排不动，Top-1 反而从 39.0% 掉到 31.7%。之前得出「K=1000 不适合做默认」的结论，
   前提正是「排序器只有 McM20」。Reranker 一旦成立，K=1000 的 lib 优势才能兑现。

**核心判据**：`K=1000 + Reranker` 的 Top-1 是否 > `K=100 + McM20` 的 Top-1（CNRS 39.0% / MP100 49%）。

## 2. 定位：只做重排，不碰前后两端

```
NN seed pool (K)  →  对称化 + LSQ  →  seeded McMaille  →  .allcells
                                                             │
                                                    ┌────────┴────────┐
                                                    │  RERANKER 在这  │   ← 本方案唯一改动点
                                                    └────────┬────────┘
                                                             ↓
                                                  Top-1 / Top-20 输出
```

明确**不做**的事：不改 seed 采样、不改 symmetrize/LSQ、不改 McMaille 参数、不引入新搜索。
好处是消融干净（池冻结，只换排序函数），且可以直接在已有 run 目录上离线迭代，不需要重跑 Mc。

## 3. 输入与特征

### 3.1 候选行来源

`.allcells` 每行 14 列，已确认字段顺序：

```
idx  seed_src  stage  n_indexed  McM20  volume  Rp  a b c alpha beta gamma  bravais  (ifile)
```

现有两个 parser 各取一半：`scripts/remeasure_l4_prim_vs_conv.py:parse_allcells` 拿到
`n_indexed/McM20/volume/Rp/params/bravais` 但丢掉 `seed_src/stage`；
`scripts/eval_rank_policies.py:parse_rows` 拿到 `seed_src/stage` 但丢掉 `volume/Rp/bravais`。
**新增统一 parser 取全 14 列**，放在 `src/pxrd_cell_indexing/rerank/allcells.py`。

> ⚠️ stage 编码在仓库里有两套注释互相矛盾。以 `result.json` 的实际计数为准，
> 即 `1=raw, 2=local_mc, 3=celref, 4=supcel`（`diagnose_mcmaille_value.py:28` 那套）。
> 落地第一步先写个断言脚本核对，不要照抄 `eval_rank_policies.py` 的注释。

### 3.2 特征分组

| 组 | 特征 | 来源 | 说明 |
|---|---|---|---|
| **A. Mc 自带** | `log1p(McM20)`, `Rp`, `n_indexed`, `log(volume)`, `stage` one-hot(5), `bravais` one-hot(8) | `.allcells` 直接读 | 零成本 |
| **B. 峰一致性** | `n_matched`, `matched_fraction`, `mean_delta`, `median_delta`, `max_delta`, `n_calc`, `density_ratio`, `de_wolff_M`, `strict_dewolff_M` | 复用 `model/fom.py:_compute_match_stats` + `search/rank.py:compute_candidate_features` | 主要算力开销，只对短名单算 |
| **C. NN 先验** | `\|log(V/V_nn)\|`, 到最近 seed 的 G* Frobenius 距离, seed rank 百分位, `seed_src` 是否落在 NN 池前 10% | `dump_flow_seed_pool` 产物 + `seed_src` 反查 | 把「NN 觉得像」这件事显式喂给排序器 |
| **D. 样本内相对秩** | A/B 组关键量在**同一样本内**的百分位：`McM20_pct`, `Rp_pct_inv`, `strict_M_pct`, `matched_frac_pct` | 现算 | 跨样本可比的关键，绝对值在不同样本间量纲差异极大 |
| **E. 几何** | `max_edge`, `min_edge`, `edge_ratio`, `angle_dev_90`, 是否接近高对称 | 现算 | 抑制退化/超胞 |

这套特征基本沿用被作废的 LTR 实验的 `FEATURE_NAMES`（44 维），
**特征设计本身没问题，作废的原因是训练数据来自 MP100 本身**（见 §4.1）。
注意 `pxrd_cell_indexing.model.classical_fom` 在当前仓库中**不存在**，
原脚本依赖的 `m_n / f_n / n_poss / n_unindexed` 需要重新实现或从 B 组等价量替代。

### 3.3 短名单策略

对每个样本取 `shortlist = top-50 by McM20 ∪ top-20 by strict_dewolff_M`（去重后约 50–60 个）。
依据是上表「命中几乎都在 rank ≤20」。B 组特征只对短名单算，
CNRS K=1000 单样本从 188 降到 ~55，特征提取成本降 3.4×。
短名单之外的候选保持 McM20 原序接在后面，保证 `lib_strict` 严格不变。

## 4. 训练数据：这次必须绝对干净

### 4.1 上次为什么作废

`third_party/McMaille/run_lab/_INVALID_mp100_supervised_rank/` 下所有脚本开头即 `sys.exit`。
根因不是特征或模型，而是：训练行取自 `mp100_seeded_phase4`，标签来自 MP100 CIF 真值。
即使做了 GroupKFold（按样本分组），**报告的 MP100 Top-1 增益仍然来自评测集自身**，
属于 benchmark leakage，数字不可信。这次的红线：

> **MP100 与 CNRS 的任何候选、任何真值，都不得进入 Reranker 的训练/调参/早停/阈值选择。
> 它们只在最终 Gate 评测时使用一次。**

### 4.2 合成训练库怎么造

数据源用训练侧的合成谱，与评测集完全无交集：

- 池：`data/processed/train_full_niggli_seed42.jsonl`（5,955,602 条），从中分层抽样
- 峰与真值：`data/dataset.py:load_sample_list` + `PXRDDataset`（LMDB `pxrd_241113_train.lmdb`）
- 内部划分：`rr_train` 4000 / `rr_dev` 1000，按 `lmdb_key` 分组，晶系分层

生成流程（新脚本 `scripts/build_rerank_dataset.py`）：

1. 从 jsonl 取样本 → 峰列表 + 真值 lattice
2. 按与评测**完全一致**的口径写 `.dat`（复用 `run_cnrs_e2e_compare.py:write_dat_trees`，NGRID=5）
3. 跑同一份 v4 ckpt 出 seed 池（K=100 与 K=1000 各一份）→ symmetrize + LSQ
4. seeded McMaille → `.allcells`
5. 逐行打 L4-strict 标签（对 primitive 真值），落 parquet

**成本**：seeded Mc 在 K=100 下约 1.5–3 s/样本，16 worker 下 5000 样本约 10–15 min；
K=1000 池更大，按 phase4 量级（~5.5 s/样本）估约 30 min。加上 seed 采样（GPU，5000 样本约 20 min），
**一轮全量数据生成在 1 小时以内**，可以承受多轮迭代。

### 4.3 域差风险（必须正视）

仓库里已有明确的反例证据：S3 合成扰动课程能把 V-mixed 抬 +6.74 pp，但 MP100 只 +0.7 pp——
**合成鲁棒 ≠ 真实谱鲁棒**。Reranker 在干净合成谱上学到的「峰匹配得好=对」，
到 CNRS 真实谱（有背景、峰形不对称、杂相、峰位系统偏移）上很可能失效。

缓解措施，三条同时上：

1. 生成训练库时施加与 CNRS 相当的扰动：2θ 零点漂移、峰位随机误差、强度阈值随机化
   （复用 `peak_imin_choices` 的多阈值协议）、随机丢峰、注入伪峰
2. 特征上偏向**样本内相对量**（D 组），少依赖绝对阈值，天然对系统性偏移更稳
3. 评测时 **MP100 与 CNRS 分别报告**，不合并成单一数字。若出现「MP100 涨、CNRS 不涨」，
   按 S3 的先例判定为**未通过**，而不是部分成功

## 5. 模型与训练

### V0（先做这个）：XGBRanker pairwise

- `xgboost 2.0.3` 环境已有（`lightgbm` 没装，不用它）
- `objective="rank:pairwise"`，group = 样本，`max_depth=6`, `n_estimators≈400`, `lr=0.05`
- 标签：L4-strict 命中为 1，其余 0（每个样本 0 或 1 个正例，天然是 pairwise 场景）
- 早停在 `rr_dev` 上按 MRR，**不看 MP100/CNRS**
- 推理：短名单打分降序；分数并列或全部很低时回落 McM20 原序

选 V0 的理由：44 维表格特征、正例极稀疏、样本量只有几千组，GBDT 比神经网络更稳、更快、更好解释。

### V0.5：与 McM20 的融合

不直接用纯模型分，而是 `score = w·model_score + (1−w)·McM20_pct`，`w` 在 `rr_dev` 上选。
这是保险丝：即使模型学歪，`w` 会被选到接近 0，退化回当前基线。

### V1（V0 达标后再考虑）：小型 set-transformer

把同一样本的所有候选当作一个集合做 listwise（softmax cross-entropy over 候选），
让候选之间互相看见（「这个体积是那个的 2 倍，可能是超胞」这类关系 GBDT 学不到）。
只有在 V0 明确达标、且诊断显示剩余错误集中在候选间关系时才启动。

## 6. 实验方案（分阶段，每阶段有明确 Gate）

### P0 — 无训练的确定性重排探底 ✅ 已完成（2026-07-31）

脚本 `scripts/eval_rerank_p0.py`，四个冻结池各跑约 15 s（特征全部来自 run 目录内的
`.dat` / `.seed` / `.allcells`，不需要重跑 McMaille）。每个策略都断言是同一候选列表的置换，
四个池的 `lib_strict` 实测完全不变，确认实现无误。

**单策略结果（ΔTop-1 相对 McM20 基线）**

| 策略 | CNRS K=100 | CNRS K=1000 | MP100 K=100 | MP100 K=1000 |
|---|---:|---:|---:|---:|
| `mcm20`（基线绝对值） | 39.0% | 31.7% | 49% | 50% |
| `fom`（de Wolff M） | **−17.1** | −3.3 | −2 | +2 |
| `strict_M` | −10.6 | −8.9 | −1 | 0 |
| `matched_frac` | −11.4 | +1.6 | 0 | −1 |
| `vol_anchor`（体积先验） | −2.4 | **+5.7** | **+5** | **+9** |
| `nn_dist`（到最近 seed 的 G\* 距离） | −0.8 | −0.8 | +3 | **+10** |
| `combo` | −0.8 | +4.9 | +4 | +3 |

**结论一：信号在 NN 先验里，不在峰匹配 FOM 里。**
这与 §3.2 的原始预期相反。`fom` / `strict_M` / `matched_frac` 这些经典峰匹配量在四个池上
几乎全是负收益，CNRS K=100 上 `fom` 更是灾难性的 −17.1 pp。原因不难理解：真实谱峰位有噪声，
而小胞的理论峰极密，de Wolff 类 FOM 会被小胞系统性地刷高。McMaille 的 McM20 已经把峰匹配这件事
做过一遍了，再算一遍同类量只是加噪声。**真正的增量信息是「NN 觉得像不像」——体积先验和 seed 邻近度。**

**结论二：三项线性组合大幅超过基线。**
score = `w₁·McM20_pct + w₂·nn_dist_pct − w₃·vol_dev`，在 48 组「均衡」权重
（`w₁,w₂ ∈ [0.25,1]`，`w₃ ≤ 0.5`）上的分布：

| 集合 | 基线 | min | 中位 | max | 超基线比例 |
|---|---:|---:|---:|---:|---:|
| CNRS K=1000 | 31.7% | 37.4% | 41.5% | 43.9% | **48/48** |
| CNRS K=100 | 39.0% | 37.4% | 40.7% | 43.1% | 34/48 |
| MP100 K=1000 | 50% | 56% | 58% | 63% | **48/48** |
| MP100 K=100 | 49% | 49% | 52% | 56% | 46/48 |

整个权重邻域都有效，不是单点噪声。取**未经调参的等权参考点** `(1, 1, 0.25)`：

| 集合 | 基线 | 等权重排 | Δ |
|---|---:|---:|---:|
| CNRS K=1000 | 31.7% | **43.1%** | +11.4 pp |
| CNRS K=100 | 39.0% | 43.1% | +4.1 pp |
| MP100 K=1000 | 50% | **58%** | +8 pp |
| MP100 K=100 | 49% | 52% | +3 pp |

**结论三：§1 的核心判据已经提前满足。**
`K=1000 + 重排` 在 CNRS 上是 43.1%，超过当前产品默认 `K=100 + McM20` 的 39.0% 达 4.1 pp；
MP100 上 58% vs 49% 高 9 pp。**K=1000 的库召回优势，一旦换掉排序器就能兑现。**

> ⚠️ **方法论警告**：上述权重是在 MP100/CNRS 上扫出来的，属于在评测集上调参，
> **这些数字不能作为最终汇报值**。P0 的合法结论只有定性的那两条（信号在 NN 先验、
> 整个权重邻域稳健有效）。权重必须在 P1/P2 的合成 dev 集上重新选定，再到冻结集上验证一次。
> 好在权重面很平（48 组里 CNRS K=1000 全部 ≥ 37.4%），对选点精度不敏感，迁移风险低。

**对后续阶段的三点修正**

1. **B 组（峰一致性）特征降级。** 从必选降为待验证，V0 首版可以完全不算峰匹配。
   这让 Reranker 变成纯粹的表格运算，单样本耗时从数十毫秒降到微秒级，短名单机制也不再必要。
2. **C 组（NN 先验）升为核心。** 需要补充更细的刻画：到最近 seed 的距离之外，
   再加 top-k seed 的距离分位、seed 密度、体积分布的分位而非仅中位数。
3. **V0 的基线要换。** 不再是「打赢 McM20」，而是「打赢 P0 的三项线性组合」。
   若 XGBRanker 赢不过一个三参数线性式，就直接采用线性式收工——这才是 B2「不需要学习式重排」
   结论在本池上的正确形态。

### P0 原始设计（存档）

在**冻结的 v4 池**上直接试几个不需要学习的排序器，回答「信号到底在不在特征里」：

| 策略 | 排序键 |
|---|---|
| baseline | McM20 降序（现状） |
| `fom` | `rerank_candidates_by_fom`（`model/fom.py` 现成） |
| `strict_M` | `strict_dewolff_M` 降序 |
| `vol_anchor` | McM20 降序，但按 `\|log(V/V_nn)\|` 施加惩罚 |
| `mcm20 × matched_frac` | 复合键 |

在 CNRS K=1000（可捞 36.6 pp）和 MP100 K=1000（19 pp）上跑。
扩 `scripts/eval_rank_policies.py:order()` 即可，**不需要跑 Mc**。

**P0 Gate**：若任一确定性策略在 CNRS K=1000 上 Top-1 ≥ +5 pp，说明信号强，继续 P1；
若全部 ≤ +1 pp，说明这批特征区分不了，先做错误分析（人工看 20 个 rank 2–5 的失败案例，
搞清楚正确解到底输在哪个量上）再决定是否投入训练。
→ **实测通过**：`vol_anchor` 单策略 +5.7 pp，三项组合 +11.4 pp。

> 这也顺带回答了 B2 的「不需要学习式重排」是否仍然成立：B2 的结论是在 **q-search 候选池**上得到的，
> 与现在 McMaille `.allcells` 池不是同一个分布。P0 会给出这一池上的确定性上限。

### P1 — 合成候选库生成（1 天）

产出 `scripts/build_rerank_dataset.py` + `data/rerank/{rr_train,rr_dev}.parquet`。

**P1 Gate**：合成库的 `lib_strict` 与命中 rank 分布，需与 MP100/CNRS 池**形状相近**
（lib 落在 55–75%，命中中位 rank 1–3）。若合成库 lib 高到 90%+，说明任务太简单，
学出来的排序器到真实数据上没用，必须加大扰动重造。这是防域差的第一道闸。

### P2 — V0 训练与内部验证（1 天）

统一 parser + 特征提取器 + XGBRanker 训练脚本，全部在 `rr_train/rr_dev` 内闭环。

**P2 Gate**：`rr_dev` 上 Top-1 相对 McM20 基线 ≥ +8 pp（内部集上应当明显更高，
因为无域差；若内部集都涨不动，外部不可能涨）。

### P3 — 冻结评测（Gate，只跑一次）

在冻结的四个池（MP100/CNRS × K=100/1000）上评测，**模型与 `w` 在此之前已完全定死**。

**P3 通过标准**（全部满足）：

- `lib_strict` 相对基线**完全不变**（重排是纯排序，任何变化都说明实现有 bug）
- CNRS K=1000 Top-1 ≥ **41%**（P0 未调参等权点已达 43.1%，取 min 侧 37.4% 与之间的保守值）
- MP100 K=1000 Top-1 ≥ **56%**（P0 权重邻域下界）
- 四个池**没有任何一个**低于各自的 McM20 基线
- 排序效率 `Top-1 / lib`：CNRS K=1000 从 46.4%（31.7/68.3）提到 ≥ 60%

**若只在 MP100 涨、CNRS 不涨** → 判定未通过，回到 P1 加扰动，不进入 P4。

### P4 — 集成与对标刷新（0.5 天）

改一个函数即可：`scripts/run_cnrs_e2e_compare.py:seeded_ordered_cells`（`run_cnrs_e2e_multithresh.py`
也是从这里 import 的），以及 `scripts/eval_reseed_arms.py:eval_sid` 的排序块，
加 `--rerank {none,fom,model}` 开关，默认 `none`，达标后再切默认。

然后重跑端到端、刷新 CNRS/MP100 两块竞品板与 canvas，写实验记录。
**若 P3 证明 K=1000+Reranker 胜出，同时把产品默认 K 从 100 改为 1000。**

**P0 后的路线判断**：既然三参数线性式已经拿到 CNRS +11.4 pp / MP100 +8 pp，
P1/P2 的首要目的**不再是「让指标更高」，而是「让权重的选定过程合法」**——
在合成 dev 集上定死权重，消除评测集调参。这是能不能对外汇报这组数字的前提。
XGBRanker 只是顺带一试；若它赢不过线性式，就用线性式，这反而是更好的结果（更简单、更可解释）。
