## 1. 背景与目标

项目对标中，经典引擎 **McMaille** 在 MP100 上有 **~65.9% mapping** 量级的历史数字（口径见 [`20260723-口径勘误`](20260723-口径勘误-JADE-Mc是mapping不是elementwise.md)）。本次工作不是“重写 McMaille”，而是：

1. **读懂**从 PXRD/峰表到候选晶胞的完整路径；
2. **定位**单样本耗时瓶颈；
3. 在**不伤精度**前提下，做**可落地的加速**（优先 OpenMP / 硬件并行）；
4. 把更激进的算法改造（代数种子）写成构想，留给后续验证。

产品场景假设：**用户拿到软件后会有单样本用法**——必须先把单样本墙钟压下来；多样本 batch 加速作为后续议题。

## 2. McMaille 工作原理（学习结论）

### 2.1 输入不是连续谱，是峰表

McMaille 吃的是：

- 波长 λ、zeropoint、模式开关 `NGRID`
- 一系列 `(2θ, Intensity)` 峰

黑盒模式 `NGRID=-3`：自动跑立方→六方/三方/菱方→四方→正交→单斜，**跳过三斜**；内部把峰做成柱状伪谱，用 **Rp**（柱重叠残差）评价晶胞好坏。

用户侧完整路径（我们用脚本复现，无 App UI，但逻辑阶段不跳）：

```text
连续谱 CSV
  → 寻峰（BG + find_peaks）+ 显式 λ/zero
  → 写 McMaille .dat（NGRID=-3）
  → mcmaille 引擎（各晶系 MC）
  → 解析候选表（含 αβγ、McM20）
  → 对照 CIF（find_mapping / 置换容差）
```

工具与产物目录：`third_party/McMaille/run_lab/`  
核心脚本：`full_pipeline_mcmaille.py`。

### 2.2 引擎内部：按晶系独立搜索

每个晶系大致是：

1. 由最大 d 间距推参数盒子 `(a,b,c,…)` 与体积上下限；
2. Monte Carlo 随机抽晶胞 → `DCELL` 建倒易度量 → `CALCUL1` 算 Rp；
3. 够好的进入局部 MC 精修（`NCYCLES`）与 `CELREF`；
4. 候选写入全局表，最后按 McM20 等 FoM 排序并给出 suggested best。

`CALCUL1` 是“心脏”：对预置 hkl 算 `1/d²`、过滤分辨率、换 2θ、与观测柱比对。原作者注释已写明：跳过 2θ、全程在 Q 空间比对，**实测只省 10–15%**——单次调用不是主瓶颈。

### 2.3 端到端锚点实测（三个样本）

| 样本 | 真解类型 | 总墙钟（单线程） | 单斜占比 | Top-1 是否命中真解尺度 |
|---|---|---:|---:|---|
| y2o3b | 高对称相关 | 较短 | 相对小 | 见对应实验记录 |
| PBSO4 | 正交 | 中等 | 显著 | 见对应实验记录 |
| **000001 (SnSe)** | 正交 Pnma | **~677 s** | **~666 s（~98%）** | 是（最小胞 / 同族倍胞） |

结论非常干净：**单样本慢 = 黑盒仍把单斜跑满，即便真解早已在正交阶段出现。**

## 3. 单斜为什么这么慢：问题规模与时间复杂度

### 3.1 搜索对象

单斜自由参数 **4 个**：`(a, b, c, β)`。黑盒不是解析求根，而是用大量随机采样覆盖 4D 盒子。

### 3.2 嵌套结构（黑盒）

```text
体积段 NRUN2 ≤ 6
  └─ 重复 NRUN = 20
       └─ 外层试探 NCEL ≤ NTIMELIM(5) = (ΔV)×200
            └─ 过门限后局部精修 NCYCLES = 2000 次 CALCUL1
```

对比正交：预算密度 `(ΔV)×20`（不是 ×200）、`NRUNS=10`、`NCYCLES=1000`。  
单斜 ≈ **更密采样 × 更多重跑 × 更长精修**，再叠加多一个角参数。

### 3.3 复杂度公式

\[
T_{\text{mono}} = O\Big(N_{\text{call}}\times(N_h + N_p N_h')\Big)
\]

- \(N_p\)：观测峰数（黑盒常用 ≤20）
- \(N_h=\min(20N_p,1000)\)：预置 hkl
- \(N_h'\)：通过分辨率过滤后的算得峰
- \(N_{\text{call}}\)：外层盲采样 + 稀疏精修带来的 `CALCUL1` 调用次数

对 `000001`（`VMON~800`）：外层试探约 **10⁶ 量级**；总调用可达 **10⁶–10⁷**。  
实测正交 ~2 s、单斜 ~666 s，差距主要来自 **\(N_{\text{call}}\)**，不是单次匹配变成了指数算法。

### 3.4 优化分层（本次形成的技术判断）

| Tier | 改什么 | 阶数变不变 | 状态 |
|---|---|---|---|
| A | `CALCUL1` 微优化 | 不变 | 天花板 ~10–15%，未作为主线 |
| **B** | **修 OpenMP，多核摊 \(N_{\text{call}}\)** | 不变（总工作量不变） | **已落地验证** |
| C | 跨晶系提前止损 | 平均情况下降 | 未做（有漏解风险） |
| D / Tier3 | 代数种子替代盲采样 | **会变** | **仅构想文档** |

## 4. OpenMP 优化：从失败到可用

### 4.1 什么是 OpenMP（本次语境）

编译时加 `-fopenmp`，用 `!$OMP PARALLEL DO` 把循环迭代分给多线程。  
McMaille 源码**本来就有** OpenMP 骨架；此前编译未真正启用，或启用后不安全。

### 4.2 当前做法（三层）

1. **循环级并行**：`DO NCEL=1,NCELLS` 分给多线程；
2. **数据隔离**：`/CAL/` 等为 `THREADPRIVATE`，每次 `CALCUL1` 互不踩踏；
3. **同步点**：只有“发布候选 / 去重”走 `CRITICAL`。

原理：百万次 MC 试探彼此近似独立（embarrassingly parallel）——**不减少工作量，只把同一份活摊到多核**，故理论上可不伤精度。

### 4.3 第一次失败：直接开并行

现象（`000001`，32 线程）：

- 墙钟虚快（1.5 s / 10.3 s vs 基线 677 s）；
- 候选出现 `NaN` / `Infinity`；
- 同参数重跑不一致；
- 总 CPU（锚点 totCPU）远低于基线 → **工作量被截断/破坏**。

初判曾指向 `NOUT`/`INTEREST`；深挖后修正：

> **真正根因是全局候选槽位 `IGC` 在三段互不互斥的命名 critical（`STORE1`→`STORE2`→`FOUND`）之间被乱序读写。**  
> `NOUT` 在各晶系并行块里其实已是 `FIRSTPRIVATE`。

比喻：多人共用一本登记册页码，只锁“写字瞬间”，不锁“从拿号到用号”全过程 → 账本乱。

### 4.4 修复

把三段 critical **合并为一个连续临界区** `CANDBOOK`（删除中间边界），使「拿槽位 → 写候选 → 去重」不可分割。  
产物：`run_lab/McMaille_omp_fixed.for` / `mcmaille_omp_fixed`。

### 4.5 单样本验证（`000001`）

| 线程 | 墙钟 | totCPU | Top-1 表现 |
|---:|---:|---:|---|
| 1（基线） | 677 s | ~677 s | 命中真解最小胞 |
| 16 ×3 | 47.8–50.3 s | 635–641 s | 2/3 精确最小胞；1/3 同族倍胞 |
| 32 | 38.7 s | 660 s | 同族倍胞 |
| 64 | 38.7 s | 692 s | 同族倍胞 |

要点：

- **无 NaN/Infinity 崩盘**；
- totCPU ≈ 基线 → 搜索未被截断；
- 16 线程性价比高（~13.5×）；32/64 进入平台（~17.5×，Amdahl + 调度）；
- Top-1 在“最小胞 vs 同族倍胞”间摇摆，与原 MC 用墙钟播种的固有随机性同类，不是“坏并行”那种损坏。

### 4.6 MP100 原版 vs 并行版（全量 100）

口径：CIF → pymatgen 模拟峰 → `NGRID=-3` → Top-1 `find_mapping(ltol=0.05, atol=3°)` vs conventional-standard 真值。

| 指标 | 原版单线程 | 并行修复版（16 线程/样本） |
|---|---:|---:|
| Top-1 mapping | **52%** | **50%（−2 pp）** |
| Top-20 mapping | 53% | **55%（+2 pp）** |
| FoM 损坏嫌疑 | 1 | 2 |
| 超时 | 0 | 0 |
| 单样本墙钟合计 | 6.82 h | **1.76 h（~3.9×）** |
| 墙钟中位数 | 17.1 s | **2.4 s** |

成对翻转：仅原版命中 8 / 仅并行命中 6 / 两边同命中 44 / 同未命中 42 → 净 −2，与总表一致。

**分晶系警示**：单斜 Top-1 **80%→60%（−20 pp）**，是总表 −2 pp 的主要来源；Top-20 不降，说明真解多半仍在池中，偏的是 suggested Top-1 / MC 路径。

说明：本次绝对命中率低于文档历史 McMaille **65.9%**，主因可能是峰表/λ/真值约定/黑盒参数差异；**本次报告强调相对对比**，不据此改写历史基线数字。

脚本：`run_lab/run_mp100_mcmaille_compare.py`；产物：`run_lab/mp100_compare/`。

## 5. OpenMP 原理小结（给后续读者）

```text
热路径（99% 时间）：各线程独立 CALCUL1          → THREADPRIVATE，无需锁
冷路径（极少数命中）：写全局候选表 / IGC / 去重   → 必须同一把 CRITICAL 包完整事务
错误示范：三段命名不同的 CRITICAL + 中间无锁代码 → IGC 乱序 → 精度崩
正确做法：一个连续 CRITICAL(CANDBOOK)             → 与单线程语义一致
```

硬件侧观察：

- 加速比随线程数**次线性**增长，约 16–32 线程后平台；
- 继续加线程会增加临界区排队与调度碎片，墙钟收益有限；
- 批量场景可叠加「样本级多进程」：每个样本内部 OpenMP，样本之间再并行（注意总核数不要过订阅）。

## 6. 算法级下一步：代数种子构想（未实施）

详见 [`20260724-McMaille单斜代数种子法构想.md`](20260724-McMaille单斜代数种子法构想.md)。

核心想法：

- 单斜 \(Q=Ah^2+Bk^2+Cl^2+Fhl\) 在给定 `(hkl)` 时对 `(A,B,C,F)` **线性**；
- 用晶带（zone）分解把 4 元问题拆成「先定 `a,c,β`，再定 `b`」；
- 复杂度目标：从盲采样 \(10^6\!-\!10^7\) 降到种子枚举 \(10^3\!-\!10^4\)；
- 架构：Python/Fortran **种子生成器** + **复用**现有 `CALCUL1`/`CELREF` 验证精修。

风险：对零点、杂质峰、伪晶带更敏感；必须先做 Python 原型 + 单斜回归，再谈接入引擎。  
**当前状态：只写构想，未写代码、未验证。**

## 8. 决策与未决事项

### 已决策 / 已证实

1. **不要**在未修复竞态前把“开 `-fopenmp` / 直接上 PMcMaille”当作默认加速手段。  
2. **方案 B（合并 CRITICAL）**可作为单样本加速主路径的候选实现，已有 `000001` + MP100 证据。  
3. 单次 `CALCUL1` 微优化不是优先投入点。  
4. 多样本加速与单样本 OpenMP **正交**，后续再系统讨论。

### 未决 / 建议下一步

1. **单斜 Top-1 −20 pp**：诊断是种子随机、排序、还是并行路径残余问题；必要时固定种子做 A/B。  
2. **扩大回归**：更多真实单斜/三斜真解样本；与历史 65.9% 口径对齐复测。  
3. **跨晶系止损（方案 C）**：正交已完美时是否跳过单斜——收益大，漏解风险需规则+回归。  
4. **代数种子（Tier 3）**：按构想文档做 Python 原型 Gate，不过关不进 Fortran。  
5. **生产默认线程数**：建议默认 16，上限 ~32；需按部署机型再标定。
