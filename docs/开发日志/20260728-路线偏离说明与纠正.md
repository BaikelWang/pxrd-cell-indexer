# 路线偏离说明与纠正（种子生成器）

> 记录一次未经报备的架构变更，以及纠正决定。

## 定的是什么

2026-07-27 17:26，PM 明确：

> 「我们就沿着**方案 A** 的基础上做：1、学一学 6m 模型 Peak Transformer，**重新设计好 output 头**；
> 2、增加数据到 6M；我们的核心目的是，通过训练我们要将方案 A 的思路模型做成
> 能够代替 McMaille 蒙特卡洛盲搜的种子生成器。」

方案 A 的定义（见 `20260727-RealPXRD微调三臂实验-执行方案.md` §臂 A）：

```
RealPXRD 预训练 ckpt (pxrd-all/last_one.ckpt)
  → 保留 A2 壳：Bert XRD encoder + CSPFlow 主体
  → 冻结 encoder/decoder body，只在 lattice 输出侧加 adapter
  → 继续 flow matching，cost_coord = 0
```

即：**用预训练好的 RealPXRD 做迁移学习到 lattice**。
「学 Peak Transformer」是指**借鉴其思路改 output 头**，不是替换整个 encoder。

## 实际做成了什么

`scripts/train_flow_seedgen.py` 构建的是：

```
PeakGeometryTransformerEncoder（自研 A2，从零初始化）
  + ConditionalFlowHead（自研，gstar6 上的条件 rectified flow）
  + 6M Niggli 数据从头训练
```

**完全没有加载 RealPXRD 预训练权重，没有用 Bert encoder，没有用 CSPFlow。**

证据：`results/flow_seedgen/full6m_equiv_off/best.pt` 的 `model_state` 只含
`encoder.cls_token` / `encoder.input_proj.*` / `flow.*` 共 107 个 key，
无 `xrd_encoder.embed_positions` 等 Bert 参数。
真正的方案 A 权重在 `results/ft_realpxrd/armA/best.pt`（含 `xrd_encoder.*`）。

## 问题定性

把「学 Peak Transformer 思路、重新设计 output 头」错误理解为
「用 Peak Transformer 替换 encoder 重做整条种子生成器」，
等于丢弃了 PM 指定的 RealPXRD 迁移学习主线，另起炉灶。

**核心过失不是理解偏差本身，而是变更了主线架构却未向 PM 报备确认。**

## 影响范围

**不受影响（全部可复用）**：McMaille 后处理与种子来源无关

- 原生 McMaille 单候选链路照搬（policy=1/2）
- 晶系码接口（`.seed` 第 7 列 + Fortran `INDIC/AFI`）
- 度规张量约束 LSQ 精修
- 反射数护栏 bug 修复（`MCM_NHKL_CAP`）
- 门控归因工具链（`.seedgate` / `diagnose_post_gate.py`）

**受影响**：仅种子生成器训练路线，及基于该模型得出的种子池指标。

## 需要同时记录的技术事实

### (1) XRD encoder 只有 3.7 万参数

本次重做时实测 `bundle.xrd_encoder`（`app.model.bert.BertModel`）：

| 子模块 | 参数量 |
|---|---:|
| `embed_tokens` | 1,184 |
| `vnode_encoder` | 32 |
| `embed_positions` (180×32) | 5,760 |
| `sentence_encoder` | 13,056 |
| `out` (32→512) | 16,896 |
| **合计** | **36,928** |
| 对比：`decoder`（CSPNet） | 12,556,800 |

`encoder_embed_dim = 32`。整张衍射图谱经过一个 32 维 transformer 压成 512 维条件向量。
所谓「RealPXRD 预训练迁移」，**权重的 99.7% 在 CSPNet decoder，谱编码侧几乎没有可迁移的容量**。

### (2) 2θ 整数量化（修正此前表述）

`batch_input` 对 2θ 做 `.long()`，`embed_positions = nn.Embedding(180, 32)`，即 1° 一格。
本次在实际加载的权重上复测（8 峰整体平移）：

| 平移量 | ‖Δemb‖ |
|---:|---:|
| +0.05° | **0.000000** |
| +0.30° | 2.894 |
| +0.80° | 21.466 |
| +1.00° | 25.848 |

**订正**：此前记的「0.8° 逐比特相同」只在所有峰都未跨整数格时成立，不是普遍结论。
准确说法是：**分辨率下限被锁死在 1°，格内任何移动完全不可见**（0.05° 严格为 0）。
indexing 需 0.01–0.05° 峰位精度，仍差两个数量级。

以上**不作为偏离的理由**，仅供路线决策与结果预期参考。

两条线的已知数据：

| 路线 | 数据量 | library strict | Top-1 strict |
|---|---|---:|---:|
| 方案 A（armA，RealPXRD 迁移） | 10k 微调 | 11% | 1% |
| 偏离产出的自研线 | 6M 从头 | 73%（K=1000） | 46%（端到端） |

**此技术事实不作为偏离的理由**，仅供路线决策参考。

## 纠正决定（PM 2026-07-28 拍板）

**按方案 A 重做**：RealPXRD 预训练 Bert + CSPFlow + 重新设计 output 头 + 扩到 6M，
跑完看真实上限。McMaille 后处理保持不动，等新种子池产出后接入。

自研 6M 线保留为对照，不删除。

### 实现

- `scripts/ft_realpxrd/models.py`
  - `a2_decoder_features()`：把原 `ArmAModel._a2_decoder_features` 提为模块级函数，两个壳共用
  - `A2ConditionedFlowHead`：`ConditionalFlowHead` 子类，条件 = `concat(冻结Bert谱特征 512,
    冻结A2 decoder 在当前迭代点的图特征 512)` → 1024。decoder 本身就是晶格去噪器，
    其特征依赖当前 z_t，所以按步计算而非静态缓存——这才算迁移，而不是「冻个编码器 + 全新模型」
  - `ArmAFlowModel`：Bert / CSPNet / time_embedding 全冻，只训 flow 头
- `scripts/train_flow_seedgen.py`：加 `--backbone {peaktf,armA}`。
  数据加载、MP100 coverage@K 评测、resume 逻辑完全复用，保证与自研线严格可比

### 规模

| | 自研线 | 方案 A 重做 |
|---|---:|---:|
| 可训参数 | 12.2M | 12.15M（仅 flow 头） |
| 冻结参数 | 0 | 12.59M（Bert 0.037M + CSPNet 12.56M） |
| 训练集 | 5,955,602 | 5,955,602（同一份） |
| 超参 | bs512 / lr1e-3 / 34ep / equiv off | 完全相同 |

运行：`tmux attach -t armA6m`，输出 `results/flow_seedgen/armA_full6m/`，日志 `logs/armA_full6m.log`。

## 附录：2026-07-29 消融后的主线再修正

纠正决定落地后，做完 Arm A 100k 消融（freeze / unfreeze / 砍 CSPNet / Fourier pos /
scratch 扩 encoder）。结果：Arm A 各变体挤在 **40–44%** library@100，
全部低于自研线（现名 **PXRD-indexer**）的 **51%**；CSPNet 死重、解冻无用、
加宽 Bert-style 从零更差。

据此 PM 再修正：

- **停止** 继续抠 Arm A 架构；6M ArmA 全冻仅作对照；
- **主线回到 PXRD-indexer**，换严口径选模（valid `<1%`）+ 训满 34ep + 4 卡从零重训。

完整数字、探针（`sample_steps` 非瓶颈）与重训协议见  
[`20260729-ArmA消融与PXRD-indexer重训协议.md`](20260729-ArmA消融与PXRD-indexer重训协议.md)。
