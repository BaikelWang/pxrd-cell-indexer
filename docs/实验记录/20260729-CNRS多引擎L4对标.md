> 日期：2026-07-29（初版）/ **2026-07-31 补齐经典引擎 + v4 刷新**

## 目标

在同一 CNRS 子集（n=123）、同一 primitive L4-strict 尺子上，对标公开可跑引擎。

## 主表（2026-07-31）

| # | 系统 | Top-1 strict | Top-20 / lib | 备注 |
|---|---|---:|---:|---|
| 1 | **Ours（v4 wide union K=100×2）** | **39.0%** | **61.0% / 64.2%** | I≥5∪I≥1 多种子 + seeded Mc |
| 2 | DICVOL91 | 17.1% | 21.1% / 21.1% | 原生 gfortran；DICVOL06.exe 不可得 |
| 3 | TREOR90 | 11.4% | 13.0% / 13.0% | 原生；11 个样本输出爆炸被 size-guard 杀掉计 miss |
| 4 | Native McMaille | 8.1% | 21.1% / 21.1% | 盲搜基线 |
| 5 | ITO13 | 1.6% | 1.6% / 1.6% | 官方要求 ≥20 峰；多数 CNRS 样本峰不足被跳过 |
| 6 | OpenAlphaDiffract | 0.0% | =Top-1 | HF 公开单模型，短角窗 5–20° |

主问题「我们是否 Top-1 最高」：**是**（39.0% ≫ 次席 DICVOL 17.1%）。

对比 7/29 旧表（Ours 当时还是 v2 K=100，Top-1 27.6%）：v4 union 再抬 **+11.4pp**。

## 协议（写死）

- 数据：`/nanolab/users/wyx/CNRS`，跳过 0 峰 `000031/096/122`
- 真值：`*_sg.cif` → SGA **primitive** 六参数
- 寻峰（经典共用）：tkh paperlike + `I≥5`；Mc/DICVOL/TREOR/ITO 取按 2θ **前 20 峰**；λ=**1.5406 Å**
- Ours 端到端：多阈值并集 `I≥5 + I≥1`，每阈值 K=100（与经典「只看 I≥5」不完全同输入——这是产品协议，不是作弊；经典侧保持其原生峰契约）
- L4-strict：`find_mapping(ltol=0.05, atol=3°) ∧ |det−1|<0.25`
- 失败：timeout / 无解 / 解析失败 / 输出超限被杀 → miss（分母仍 123）

## 已知限制

1. **TREOR 暴走**：少数低对称样本会写出数 GB `.imp/.con`；已加 `--max-output-mb`，超限杀进程并计 miss（11/123）。
2. **ITO 峰数门槛**：文档要求约 20–35 峰；CNRS 在 I≥5 下大量样本 <20 → 跳过。不是 harness bug。
3. **Ours vs 经典输入不完全相同**：Ours 用多阈值并集是已定产品协议；若要做「同峰表」消融，可另开一臂只喂 I≥5。

## 结论

1. 在完整可跑引擎表上，**Ours Top-1 仍最高，且相对次席 DICVOL 有 +22pp 差距**。
2. 经典三引擎已从 `unavailable` 填实；OpenAlpha 公开权重仍未形成 L4 竞争。
3. 下一轮若要对齐「同峰表」公平性，单独跑 Ours@I≥5-only 对照即可，不必改主表口径。
