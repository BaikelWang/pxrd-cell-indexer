# 20260727 Mc 接纳池 vs RealPXRD K=100：种子级对比

> **脚本**：`scripts/compare_seed_generators.py`  
> **数据**：`results/seed_gen_mc_vs_rpxrd_k100.json`  
> **口径**：loose = `find_mapping(0.05, 3°)`；strict = loose 且 `|det−1|<0.25`

## 重要口径说明

原生 McMaille **不会落盘盲采样中间态**。`.imp` 里的 FINAL LIST 是
**过 Rp / n_indexed 门限之后**、再经局部 MC / SUPCEL / CELREF 的**接纳提案表**。
这是我们能拿到的、最接近「Mc 蒙特卡洛搜索产物」的种子池。

RealPXRD 侧：A2 xrd-only，`num_evals=100`，推理期消融（dummy atom + 冻结坐标）。

因此这不是「原始盲采样点云 vs NN 点云」，而是：

**Mc 搜完并过滤后留下的提案** ↔ **RealPXRD 直接吐出的 100 个种子**。

## 种子性格：两套完全不同的分布

### 1. 体积尺度

每个样本池的「体积中位 / V_prim」分桶：

| V / V_prim | Mc | RealPXRD |
|---|---:|---:|
| < 0.4 | 0 | **79** |
| 0.4–0.75 | 13 | 18 |
| 0.75–1.25（正确量级） | **23** | **3** |
| 1.25–2.5 | 18 | 0 |
| > 2.5 | 32 | 0 |
| 空池 | 14 | 0 |

- **Mc**：体积簇在真值附近或略大（常规/有心胞常见），空池 14%。
- **RealPXRD**：系统性偏小，**79/100 样本的池中位体积不到原胞的 40%**——典型亚胞云。

### 2. 映射行列式

有 mapping 时 best \|det\|：

| | ~1 | ~2 | ~4 | 其他/无 |
|---|---:|---:|---:|---:|
| Mc | **28** | 9 | 0 | 63 |
| RealPXRD | 4 | 6 | 20 | 70 |

Mc 一旦能 mapping，多半就是 `|det|≈1`；RealPXRD 的「命中」大量是 `|det|=4/5/8…` 的亚胞/倍胞关系——所以 loose 高、strict 崩。

### 3. 对称性形态

Mc 池里 **37% 近正交、30% 近六方**——因为它按晶系搜、强制角度约束。  
RealPXRD 几乎全是自由三斜（5% 正交、1% 六方）——ODE 采样没有晶系先验。

### 4. 多样性 vs 纯度

RealPXRD 体积 bins 更多（23.9 vs 4.2），看起来「更散」；  
但散的是**错误尺度上的噪声**，不是正确原胞附近的覆盖。  
Mc 池小而尖：过门限后留下的是少数高质量提案。

## 互补性：几乎不重叠

**prim strict：**

| | 样本数 |
|---|---:|
| 仅 Mc 命中 | **28** |
| 仅 RealPXRD 命中 | 4 |
| 两者都命中 | **0** |
| 都没命中 | 68 |
| 并集 | 32 |

**两者 strict 命中集合完全不相交。**  
RealPXRD 那 4 条独立命中，Mc 侧要么空池、要么提案在别的尺度上。

按晶系（prim strict）：

| 晶系 | n | Mc | RealPXRD |
|---|---:|---:|---:|
| cubic | 15 | 0% | 7% |
| hexagonal | 15 | **40%** | 0% |
| monoclinic | 15 | **60%** | 0% |
| orthorhombic | 20 | **45%** | 5% |
| tetragonal | 15 | 20% | 0% |
| triclinic | 5 | 0% | 0% |
| trigonal | 15 | 7% | 13% |

Mc 强在单斜/正交/六方；RealPXRD 几乎只在立方/三方捡到零星 strict。  
三斜两边都是 0。

---

## 一句话结论

这两套「种子」不是同一类物体：

- **Mc 接纳池**：少、尖、体积对、对称性强约束 → strict 28%，但 14% 样本交白卷。  
- **RealPXRD K=100**：多、散、系统性偏小、自由三斜 → loose 75% 的「假繁荣」，strict 只剩 4%。

用 RealPXRD 去「喂」Mc 的后处理（SUPCEL/LOCAL_MC/CELREF），等于拿一堆亚胞去跑为「已过门限的好苗子」设计的精加工——这正是融合算法不靠谱的根因之一。
