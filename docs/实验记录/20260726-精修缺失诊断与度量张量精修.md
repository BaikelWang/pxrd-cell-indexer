# 20260726 我方算法诊断：缺失的精修阶段 + 度量张量精修实现

## 一、我方当前算法是什么

`mp100_seeded_phase4` 的实际流水线（读 `result.json` / `.allcells` / `.seed` 反推）：

1. **种子**：神经网络对每个样本给出 100 个基础晶胞，按 7 个晶系投影展开成约 1193 个种子（`.seed`）
2. **seeded McMaille**，四个阶段写进同一个 `.allcells` 库：

| stage | 含义 | 平均行数/样本 |
|---|---|---:|
| 1 `raw` | 种子本身 | 1193 |
| 2 `local_mc` | 种子邻域蒙特卡洛 | 1193 |
| 3 `celref` | **晶胞精修** | **0** |
| 4 `supcel` | 超胞派生 | 902 |

3. **排序**：按 McM20 取 Top-20

## 二、不足之处

### 1. `celref` 阶段是死的

phase3 和 phase4 全部 100 个样本，该阶段产出恒为 0 行。派生出来的超胞从未回到衍射峰上做过拟合。

### 2. 各阶段对峰的拟合质量

覆盖率 = 前 20 条观测峰中，与理论反射差 ≤ 0.05° 的比例。

| stage | 最佳覆盖率中位数 | 覆盖率 ≥0.8 的样本占比 |
|---|---:|---:|
| raw（种子） | 0.20 | 5% |
| local_mc | 0.70 | 39% |
| supcel | 0.18 | 5% |
| 真原胞 | 1.00 | 98% |

`local_mc` 确实在精修（0.20 → 0.70），但 `supcel` 把误差按倍数放大后没人收拾，掉回 0.18。

### 3. 精修与扩胞谁也替代不了谁

- 精修改不了 `|det|`：亚胞精修完还是亚胞
- 扩胞改不了精度：基胞 ~1% 的度量误差乘上去，2θ 偏移 ~0.3°，远超 0.05° 的匹配容差

必须串起来用。

### 4. 排序偏袒超胞

只按覆盖率排序必然选超胞——超胞天然能解释所有峰。经典 FoM 用「可能反射数 N_poss」惩罚这一点，我们之前没用。

## 三、本次做了什么

### 新增 `scripts/cell_refine.py`

**度量张量线性精修**。`Q = 1/d² = h²G₁₁ + k²G₂₂ + l²G₃₃ + hk·2G₁₂ + hl·2G₁₃ + kl·2G₂₃`
对倒易度量张量的六个分量是**线性**的，所以每轮精修就是一次普通最小二乘，比在
`(a,b,c,α,β,γ)` 上做非线性优化稳健得多。指派窗口用 Q 空间相对容差并逐轮收紧。

验证：真胞扰动 0.5% → 精修后精确还原（cov 0.19→1.00，残差 3e-9）。

**对称性约束精修**。每个晶系都是六维参数向量的一个线性子空间，
约束拟合仍是最小二乘（解 `(A·B)z = y`，`p = B·z`）。

**spglib 吸附 + 约束精修**。近对称胞会把重合反射劈开，N_poss 暴涨、M_N 崩塌。
先用 spglib 恢复精确对称（形状对、尺度略偏），再用约束精修把尺度拉回来。

### 顺带修掉两个 bug

- `hkl_grid` 索引上限写死 12，长轴/斜胞的反射被截断，N_poss 少算导致 M_N 虚高
  10⁵ 倍，病态胞因此霸榜（修正后该胞 M_N 从 8.9e7 掉到 408）
- 波长 1.5406 与 MP100 模拟用的 1.54184 不一致

### 新增评测脚本

- `scripts/eval_pool_refine_rank.py`：池 → 精修 → M_N 排序
- `scripts/eval_expand_refine_rank.py`：池 → HNF 扩胞 → 精修 → 对称化 → M_N 排序

## 四、结果（10 样本冒烟，真值 = 原胞）

命中 = `find_mapping(0.05, 3°)` 且 `|det−1|<0.25` 且 覆盖率 ≥0.8

| 配置 | lib | Top-20 | Top-1 |
|---|---:|---:|---:|
| 仅精修 | 10% | 10% | 10% |
| 扩胞 + 精修 | 30% | 10% | 10% |
| 再加对称化 | 30% | 10% | 10% |

**生成端有效果（10%→30%），排序端没动。**

## 五、关键结论：瓶颈在生成，不在排序

对三个样本把所有过覆盖率门槛的候选全部对称化后，对比真胞与库内最优候选的 M_N：

| 样本 | 峰数 | 库内最优 M_N | 真胞 M_N | 首个命中排名 |
|---|---:|---:|---:|---:|
| mp-1183073 | 5 | 1.95e9 | 1.42e6 | 1006 |
| mp-1029457 | 16 | 26.8 | 9.29e5 | 无 |
| mp-1194549 | 32 | 6.3 | 3.24e5 | 94 |

**真胞的 M_N 比库内最优候选高 4–5 个数量级。** 只要真胞进了库，M_N 一眼就能把它挑出来；
现在挑不出来，纯粹是因为库里根本没有它——扩胞只用了 40 个基胞，正确的基没被包含。

一个例外要如实记下：**mp-1183073 只有 5 条峰，6 参数拟合本身欠定**，
存在多个都能精确解释全部峰的胞（如 V=139.7 的四方胞与真菱方胞体积相同），
这种情况任何 FoM 都无法分辨，不是排序算法的问题。

另外，对全库做对称化耗时 164–284 秒/样本，不可用于量产，只能作为诊断手段。

## 六、下一步

瓶颈已定位在生成端。方向是扩大扩胞覆盖（更多基胞 / 更高指数），
而不是继续调排序权重。
