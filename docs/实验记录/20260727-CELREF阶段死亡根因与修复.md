# 20260727 seeded McMaille 的 CELREF 阶段为何恒为 0 行：根因与修复

> 承接 `20260726-精修缺失诊断与度量张量精修.md` 里记录的现象——`mp100_seeded_phase4`
> 全部 100 个样本 `stage=3 (celref)` 产出恒为 0 行。本文定位根因、落地修复并做 A/B。
>
> **代码**：`third_party/McMaille/run_lab/McMaille_seeded.for`（原版备份 `*.bak_precelref`）
> **产物**：`third_party/McMaille/run_lab/mp100_seeded_phase5/`、`results/celref_fix_ab_mp100.json`

## 一、定位方法

在 `McMaille_seeded.for` 的 `8023` 写回块里给每个拒绝分支加计数器，编译成临时二进制
跑 `mp-1029457`（1197 个种子）：

```
DBGSUM NaN=1197  len=0  ang=0  angsum=0  same_as_MC=0  vol=0  noindex=0  ACCEPTED=0
```

1197 个种子**全部**因为「胞参数是 NaN」被拒。再在 `8200` 插入点前后打印 `BB(1)/BB(2)`：

```
PRE  seed 1 stage 1 LHKL=2  BB1=0.00000000  BB2=1.54183996
POST seed 1 stage 1         BB1=NaN         BB2=1.54183996  BB3=NaN
PRE  seed 1 stage 4 LHKL=2  BB1=NaN         ...
PRE  seed 2 stage 1 LHKL=0  BB1=NaN         ...
（此后 BB1 恒为 NaN）
```

## 二、两个叠加的 bug

### Bug 1：`CELREF2` 把零点污染成 NaH，且污染是永久的

`CELREF2` 除了精修晶胞，还会把**精修后的零点偏移写回共享数组 `BB(1)`**：

```fortran
      DO 351 I=1,8
351   BBB(I)=B(I)
```

调用点 `AFI(1)=1`（零点自由）+ `AFI(3..8)=1`（6 个胞参数）→ 7 个自由参数。
第一个种子只有 `LHKL=2` 条标定线，法方程奇异，最小二乘返回 NaN。

`BB` 是主程序里跨调用复用的数组，`BB(1)` 一旦变成 NaN 就再也回不来，
**后续 1197 次调用全部 NaN 进 NaN 出**。

每个 `console.log` 末尾 `FINAL VALUES` 那行标准差全是 NaN，是同一个污染的外部表现。

### Bug 2：`CELREF2` 返回的是倒易胞，写回时被当成直接胞

修掉 NaN 之后，拒绝原因变成 `len=538`（胞参数落在 `1.0 ≤ a ≤ 80` 之外）。打印实值：

```
BB(3) = 0.2441        CELMC(1) = 4.0963        1/0.2441 = 4.0965
```

`CELREF2` 内部先 `CALL INVER` 把胞转到倒易空间做最小二乘，**结束时没有转回来**：

```fortran
      DO 340 I=1,3
      BB(I)=B(I+2)
  340 BB(I+3)=B(I+5)*RD     ! 倒易角度转成度，长度仍是 a*, b*, c*
```

stock McMaille 从不读这个返回值——它只用 `DDT/DDQ` 算 M20/F20，
`BBB` 的写回在原版里是被忽略的副作用。而 Phase-2 的 `8023` 写回逻辑
把 `BB(3..8)` 直接当成 (a,b,c,α,β,γ) 用了，每个长度都是 0.2–0.3 Å 量级，
必然被范围检查拦掉。

**两个 bug 的关系**：Bug 1 在最前面就把一切变成 NaN，所以 Bug 2 在观测上被完全遮蔽。

## 三、修复

三处改动，均在外部种子模式分支内，不影响 stock 搜索路径。

**1. `8200` 插入点：每次调用前重置零点/波长，并冻结这两个参数（7 参数降到 6）**

```fortran
      AFISV1=AFI(1)
      AFISV2=AFI(2)
      BB(1)=0.
      BB(2)=SLABDA
      AFI(1)=0.
      AFI(2)=0.
      CALL CELREF2(INDIC,BB,AFI,LHKL,TH3,IHKL,DDT,DDQ)
      AFI(1)=AFISV1
      AFI(2)=AFISV2
```

**2. `8023` 写回块：倒易胞转回直接胞**

```fortran
      RDINV=180./ACOS(-1.)
      DO 8210 IBI=1,8
8210  BBINV(IBI)=BB(IBI)
      BBINV(6)=BBINV(6)/RDINV
      BBINV(7)=BBINV(7)/RDINV
      BBINV(8)=BBINV(8)/RDINV
      CALL INVER(BBINV,DBINV,VOLINV,0)
      BB(3)=BBINV(3)
      ...
```

`INVER` 是对合映射，再作用一次即回到直接空间；注意它要求角度是弧度。

**3. 主程序声明 `BBINV(8),DBINV(8)`**

编译：

```bash
cd third_party/McMaille/run_lab
gfortran -O3 -ffixed-line-length-132 -std=legacy -fallow-argument-mismatch \
  -o mcmaille_seeded McMaille_seeded.for
```

## 五、结论

1. **CELREF 死亡是真 bug，已定位并修复**，修复本身是正确的：精修阶段恢复产出，
   最优 Rp 从 0.140 降到 0.071。
2. **但它不是 Top-1 的瓶颈。** K=1/5 反而略跌，K=10~30 略涨，幅度都在
   McMaille 自身 MC 随机性的量级内（参见 `20260724-McMaille-MP100原版vs并行版对比.md`
   记录的 ±2pp 摇摆），不能算实质收益。
3. **strict 口径与库的 strict 可达性纹丝不动（9% / 10%）。** 原因是结构性的：
   CELREF 只是把已有的胞原地精修，不改变 `|det|`，不会凭空造出正确体积的原胞。

这与 `20260726-亚胞还原原胞-Phase1.md` 的判断一致：**真正卡住的是「正确体积的原胞
根本没被生成出来」**，不是排序、也不是精修。精修只能让池子里已有的胞更准。

`fix` 的价值在于：从此精修阶段可用，后续做「先精修基胞、再扩胞」这类流程时
不必再自己在 Python 侧重写一遍度量张量精修。

## 六、踩坑记录

批量跑 `mcmaille_seeded` 时，若用**绝对路径**调用二进制且该路径超过 80 字符，
程序会把 `argv[0]` 截断进 `CHARACTER*80` 缓冲区，导致：

```
Fortran runtime error: Cannot open file '/nanolab/.../McMaille/run_l'
```

改成在样本目录内用相对路径 `./mc` 调用即可。
