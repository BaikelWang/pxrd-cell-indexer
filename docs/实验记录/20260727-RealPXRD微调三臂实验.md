# RealPXRD 微调三臂实验（2026-07-27）

> 规格：`docs/开发日志/20260727-RealPXRD微调三臂实验-执行方案.md`  
> 汇总：`results/ft_realpxrd/summary_three_arms.json`

## 1. 结论（先看这个）

在共享 10k/1k 子集上微调后，MP100 **原胞 library strict（K=100）**：

| 方案 | lib strict | Top-1 strict | best \|det\| 中位 | 中位 V/V真 |
|---|---:|---:|---:|---:|
| A2 基线（无微调） | **4%** | ~3% | 5.0 | 0.26 |
| **臂 A**（A2 壳 + flow + lattice adapter） | **11%** | 1% | **3.5** | **1.10** |
| 臂 B（冻 Bert + lattice head） | 7% | 3% | 34.5 | 2.61 |
| 臂 C（Fourier 位置 + 部分解冻） | 8% | 6% | 29.5 | 2.82 |
| 自研 6M peaks-only（天花板） | 39% | 37% | 1.0 | ~1 |

- **未达到**预设成功线（≥15%）。
- 相对 A2 有提升（4%→11%），但离 6M 天花板仍远。
- **臂 C 并未显著超过臂 B**：在本设定下，仅替换连续 Fourier 位置 + 10k 微调，不足以把 Bert 表征拉到可用 indexing 精度。
- 臂 A 体积尺度最合理；B/C 的 Bravais 扩展把松召回抬到 ~90%，但 \|det\| 很大（倍胞/亚胞）。

## 2. 实验设置

- 子集：`results/ft_subset_10k_seed42.json`（train 10k / valid 1k，seed=42）
- 预训练：`archive/RealPXRD-Solver/pretrained/weight/2501/pxrd-all/last_one.ckpt`
- 代码：`scripts/ft_realpxrd/` + `scripts/run_ft_realpxrd.py`
- 评测：`l4()` / `truth_cells()`，与项目既有口径一致
- B/C Top-K：`build_top_k_candidates` + `EXTENDED_LENGTH_SCALE_FACTORS`

训练（早停 patience=15）：

| 臂 | best epoch | valid 监控 |
|---|---:|---|
| A | 20 / 35 | flow MSE ≈ 0.526 |
| B | 74 / 89 | SmoothL1 ≈ 0.215，rel_len≈0.151 |
| C | 80 / 95 | SmoothL1 ≈ 0.220，rel_len≈0.149 |

## 3. 解读

1. **冻 Bert（B）几乎吃尽整数 2θ 量化误差**，下游 MLP 只能学粗糙尺度 → strict 仅 7%。
2. **臂 C 换 Fourier 后 Top-1 从 3%→6%**，说明连续位置有用，但 10k + 只解冻末层不够重建峰位敏感表征。
3. **臂 A 仍继承量化编码器**，却靠流采样多样性把库召回推到 11%，体积比接近 1——说明「生成多样性」比「单点回归 + Bravais 扩展」更贴 indexing 需求，但也证明瓶颈仍在 XRD 表征。
4. 与自研 PeakTransformer Fourier 修复（5%→97%）对比：彼时是**从头训大模型**；此处是**短微调残损编码器**，不可直接类比。

## 5. 建议的下一步（按优先级）

1. **不要**继续在 RealPXRD 整数 Bert 上堆 adapter 指望突破 15%。
2. 若仍想救 RealPXRD 线：臂 C 式 Fourier **从预训练阶段重训**（或至少全量解冻 + >>10k），再评。
3. 融合流水线优先切到 **自研 6M peaks-only** 做种子（此前已验证 reseeding 把 Top-20 strict 7%→31%）。
4. 扩胞/HNF 仍可作为松种子补丁，但不能替代好的原胞种子分布。
